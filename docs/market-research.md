### 차별성 [판단]
1. **내 조건으로 계산**: 남은 연차, 한 번에 쓸 최대 연차, 최소 연휴 길이, 긴 연휴 우선/합계 우선, 공휴일 미적용(5인 미만), 대체공휴일·노동절 개별 설정, 회사 휴무일, 확정 연차, 연차 불가 기간.
2. **최적화가 정확함**: 겹치지 않는 연휴 조합을 동적 계획법으로 계산하고 완전 탐색과 결과가 같음을 테스트로 확인.
3. **다음 행동까지 연결**: .ics 캘린더 저장, 연차 신청 문구 복사, 조건이 담긴 공유 링크, 해당 날짜가 입력된 항공권·숙소 검색.
4. 회원가입 없음, 입력값 서버 전송 없음.

## 4. 수익 구조

- 주 수익모델: **여행 제휴(트립닷컴)**. 연휴 날짜가 정해진 사용자가 바로 그 날짜의 항공권·숙소를 검색 → 예약 시 수수료.
- [사실] 트립닷컴 파트너 페이지: "up to 7% commission" (https://www.trip.com/partners/, 2026-10-14). 세부 요율·쿠키 기간·승인 조건은 공식 페이지에서 확인하지 못함. 제3자 디렉터리는 쿠키 30일(웹)로 표기.
- [사실] 날짜 입력 검색 링크는 8개 목적지 모두 실제 노선·날짜 결과 페이지로 열림을 내장 브라우저로 확인 (도쿄·오사카·후쿠오카·타이베이·홍콩·다낭·방콕·제주).
- 현재 상태: **제휴 미가입·미연결**. 링크는 일반 검색 링크이며 수수료가 발생하지 않는다.

### 예상 매출 계산식 (가정치, 관측값 아님)
`월 매출 = 월 방문 × 여행 버튼 클릭률 × 예약 전환율 × 평균 예약액 × 수수료율`

| 가정 | 값 |
|---|---|
| 여행 버튼 클릭률 | 8% |
| 클릭 후 예약 전환율 | 2% |
| 평균 예약액 | 60만 원 |
| 혼합 수수료율 | 3% (항공은 낮고 숙소가 높다고 가정) |

→ 월 1,000 방문: 약 2.9만 원 / 1만 방문: 약 29만 원 / 10만 방문: 약 288만 원.
모든 비율이 미검증 가정이다. 측정 도구 연결 후 실제 클릭률로 대체해야 한다.

### 광고(AdSense)를 주 모델로 하지 않은 이유 [판단]
github.io 하위 경로 사이트는 루트 도메인 소유 확인(ads.txt)이 어렵고, 계산기 특성상 체류 페이지 수가 적어 광고 단가가 낮다. 여행 제휴는 '날짜가 정해진 순간'이라는 구매 직전 맥락을 쓴다.

## 5. 초기 유입 실험 (1개)

- **대상·경로**: "2027 연차 꿀조합", "2027 공휴일", "2027 대체공휴일"을 검색하는 직장인 → `/2027-holidays/` 콘텐츠 페이지(엔진 계산 결과 기반, 출처 표기) → 계산기 CTA.
- **필요 조치**: Google Search Console·네이버 서치어드바이저에 사이트 등록과 사이트맵 제출 (소유자 인증이 필요해 사용자 작업).
- **유효한 관심 기준**: 방문 대비 `plan_run`(직접 조건 변경 후 계산) 30% 이상, 그중 `ics_download`·`copy_request`·`share`·`outbound_*` 중 하나 이상 15% 이상.
- **수정 기준 (4주 후)**: 목표 검색어 노출 100회 미만 → 제목·설명·본문 보강. 방문 300 이상인데 plan_run 30% 미만 → 첫 화면 문구·입력 단순화. 여행 클릭률 2% 미만 → 여행 CTA 위치·문구 수정, 5% 이상 → 제휴 승인 우선.
- 측정은 GoatCounter(쿠키 없음, 소규모 사업 무료 허용: https://www.goatcounter.com/) 코드를 config에 넣으면 시작. 현재 미연결.
